# Changelog

All notable changes to ZPlay will be documented in this file.

## [1.6.2] - 2026-10-12

- Home's own top row is no longer a one-way arrival. The shell hands a Down out of the bar onto the calendar, and that hand-over is a focus request, which the framework's directional search records nothing about - so a Down out of the calendar into the page left the calendar as the node Up was remembered to return to, and every Up after that spent itself putting the remote back where it already was. The ring stayed on the glyph, the page did not move, and the bar - the only way off Home - could not be reached at all, which left Back as the only way out. Up out of a page's own top row is a hand-over of its own now, from the row the remote came in from, in the same shape as the one that took it down: the arrival is reversible in both directions whatever the traversal state happens to remember.
- The focus ring on the dead-stream overlay's primary action is visible. That action's fill is the accent and the app's ring is the accent too, so the ring painted on it was the same colour as the shape it marked and the two read as one - the same defect the See All pills were fixed for, where the answer was to move the pill's fill. Here the fill is what makes the button the primary action of the pair, so the *ring* is what moved: it takes the ink Material already prints that button's label in, chosen against that exact fill. The outlined neighbour, whose fill is the overlay's own scrim, keeps the accent like every other control in the app, and both buttons' sizes, fills and hit targets are untouched.

## [1.6.1] - 2026-10-11

- Every control in the player now says where the remote is with the app's own ring. The transport was the last place in ZPlay that answered focus with something else: a translucent grey disc on the buttons, and two hand-rolled accent rectangles on the seek bar and the volume track that were near-copies of the ring rather than the ring itself. All of them wear the one component now, at the radius of the shape they sit on, and the icon buttons keep their own brighten-and-scale as well. One of them was worse than inconsistent: the seek bar's remaining-time toggle was built from a widget that read its own focus state and then ignored it, so it painted *nothing* on focus — a control a remote could land on and not see. The transport's tests walk all twelve controls and assert the ring is under the focused one, lit, and the only lit ring on the screen.
- A source row's own action is reachable from a couch. The Watch Sources list is a single column, so a horizontal search finds nothing to the right — which meant the row's copy-magnet button existed only for a pointer, and a television could not copy a magnet link at all. Right now steps into the row's action, the centre button copies and does not start the stream, Left returns to the row with the row's ring coming back as the action's goes out, and Down walks on to the next row (whose own action is reachable the same way). A row with no magnet link leaves Right exactly as it was, so nothing about a direct-link row changed.
- The hero is never pillarboxed. The poster tail of the artwork chain fitted its frame to the band's height and pinned it right, which on a 960 dp canvas draws 219 dp of artwork and leaves 741 dp of hard black beside it — the report's "hard vertical edges and black bands at both sides". One rule covers every candidate now: fill the band, anchored to the top, because a poster's upper third is its title treatment and a wide still's is its faces. The same crop the strip behind the rails already uses, so the two agree.
- Search's shelves are the shelves Home draws. The same addon rail — same feed, same heading — rendered 16:9 on Home and 2:3 posters under Search, because Home had deliberately opted into the landscape card (a seven-wide row of posters at ten feet is mostly unreadable captions) and Search had never asked for a shape, taking the default. Search renders the landscape card now; every other page keeps the poster default it had.
- The Live TV hero no longer leaves a hole where art should be. A featured channel with no backdrop reserved the picture's height and put nothing in it — about 120 dp of empty band above the title. The band fills instead of shrinking (every slide in the reel shares one height, so collapsing it would move the page under the reader as the reel turns, and a URL that exists but fails would collapse at the exact moment art was due): the channel's own short code stands in the empty area, dimmed, and a backdrop that 404s swaps to it without re-requesting the dead URL.
- Releases carry an Android x86_64 APK. They shipped arm64 and v7a only, so a release could not be installed on an emulator at all and every emulator test needed a locally built APK. The version-code scheme is unchanged — v7a keeps `+1000`, arm64 `+2000`, x86_64 `+4000` of the pubspec build number.

## [1.6.0] - 2026-10-11

- The search field has a microphone wherever the platform has a recognizer. Typing is the one thing a television remote cannot do: the field is a text field, and on a leanback device spelling a title means walking an on-screen keyboard one key at a time, which is long enough that a search is usually abandoned before it is finished. The control sits beside the field and is there before anything is typed, and it hands the work to whichever recognizer the device already carries, through `RecognizerIntent`: the activity that answers owns the microphone — the OEM's far-field one on a television, the phone's own on a handset — and the finished sentence comes back to fill the field and run the search, exactly as pressing one of the recent-search chips does. Nothing is bundled and no acoustic model is shipped, the microphone owns only the sentence it is handed, and where the platform has no recognizer the control is not built at all, because a microphone that cannot listen is worse than no microphone. `RECORD_AUDIO` is declared and requested at the point of use, and the manifest names both the recognition service and its activity, which from API 30 are otherwise invisible to an app that has not asked — a hidden activity resolves to nothing, which would report a working television as having no recognizer.
- The card that grows on focus is the selected card, not a window over the page. The pop doubled the card and blew it up with a paint scale, which multiplied the 3 dp focus ring to 6 dp along with the caption and the badge; nothing told the eye which card the screen was about; and a wide dark shadow floated the whole thing off the rail. It grows by a third now, laid out at the size it is painted at rather than scaled, so the ring, the type and the badges keep the metrics they were designed at. On a television everything the card is not goes down a stop behind it as the pop opens — the focus treatment the old one was missing — the shadow is small enough to sit the surface off the rail instead of levitating it, and the details fade and rise into place after the card's own growth is under way rather than arriving with it. The card's own caption fades out as the panel's title fades in, so a title is printed once rather than twice forty dp apart, and the facts line is secondary text rather than the accent — the colour this app reserves for what the user can act on, which made a year and a runtime read as a link.
- A focused grid cell stays under the page's own chrome. Both grids put the popped cell in their first row, so a copy pinned to the window's edge was drawn 124 dp above it and painted over the toolbar and the genre pill row — the pills half-visible beside it, which reads as broken rather than as layering — and over the catalog chip row on Browse the same way. The page now declares where its own content begins, and the pop treats the band below that line as the window it has to fit, so a grid page lets the card grow less; the panel answers a tight page by dropping the genres line and holding its synopsis to two lines, which is what closes the arithmetic on a 540 dp canvas.
- A title page opens on its primary action, with the ring on it. The route opened on its own focus scope with nothing focused at all — no ring anywhere on the canvas — and the first press of Down reached the back control, whose OK left the page, so the screen's opening state was "no focus" followed by an accidental exit. The page claims its own primary action on the frame its content appears, the back control and the genre pills and the synopsis toggle wear the same ring as everything else, and a page opened by pointer claims nothing, because the ring is a television's answer to a question a mouse never asks.
- The Home page's own top row is reachable from the bar above it. The calendar and the quiz glyphs sat outside the traversal graph: Down from the bar's last item skipped them for the rail below, and Up from the rail was a dead key that left the ring where it was, so two controls drawn on every Home screen could not be pressed by remote at all. The row's controls are focus targets now, the page publishes the first of them to the shell, and the bar hands a Down over to it when it is in the same column rather than guessing a neighbour.
- The hero stands down when the remote leaves it, and the television stops getting pointer furniture. The hero's buttons were painted under a rail card's pop, which clipped "More Info" to "e Info"; they now fade while focus is elsewhere on a remote-driven screen, keeping their box so nothing moves, and stay exactly as they were for a finger. The scrolling grab-pill — a 55 by 412 dp chevron strip pinned over the cards — was gated on the window being wider than 800 dp under a "desktop only" comment, which a 960 dp television satisfies; it asks the form factor now, which is the question it meant. The hero's media-type chip moved inside a 5% margin instead of sitting in the last ten dp of the screen, and the carousel dashes stopped being focusable on a television, where Up out of the first rail used to land on a 16 by 3 dp mark.
- Four places the television was cutting a sentence in half. The series page's own call to action read `Play Episod…` because the pill had been given the poster's width — 177 dp, which leaves 101 dp for a label that needs 102 — so the column is the wider of the two now and the action is spelled out. The Library's second tab clipped to `Downloa…` while the row had hundreds of dp spare, because its width budget was measured with a bare painter over a raw style carrying no font family, in the engine's fallback face rather than the loaded one and without the user's text scale. A dialog body could show half a line of prose above its footer, and the update box could clip its changelog mid-word; both fold their viewport onto the last whole line that fits now, measured from the line boxes actually painted, which is the only way to be certain when the blocks inside share no line grid.
- The bar marks the destination that was actually chosen. Choosing Live TV routed to Browse with the Live TV tab, and the bar then underlined Browse while the Live TV item kept the ring — the bar reporting a different destination from the one the user picked. The chosen row carries the mark now, and Browse's own press takes it back when Browse is what is on screen.
- A focused card's pop stays under the page's own chrome on a television. On both grids the popped cell is in the *first* row, so a copy pinned to the window's edge was drawn 124 dp above it on See All and painted over the 56 dp toolbar and the genre pill row — the pills left half-visible beside it, which reads as broken rather than as layering — and over the catalog chip row on Browse the same way. The page now declares where its own content starts (`PageContentTop`: 136 dp of toolbar, pill row and gap on See All, the header plus one gap on Browse), and the pop treats the band below that line as the window it has to fit: the growth spends the band rather than the whole 540 dp canvas, so a grid page lets the card grow less, and the copy's top can no longer be pinned above the line. The details panel answers such a page too — no genres line, and a two-line synopsis reserve instead of four — because a 307.58 dp cell under 136 dp of chrome leaves the panel that much and no more; where even that does not fit, the card keeps its resting size rather than shrinking below its own cell, and the panel's last line is what the window's bottom edge cuts. A page that declares nothing, every rail in the app, is the pop it was, term for term.

- A television can see which genre pill the remote is on. On the See All grid the pills answered two different questions with one signal: the filter in force was an opaque accent fill, and focus painted nothing at all. A remote therefore walked the row invisibly — ten presses of Right left the screen unchanged — and the OK that followed applied whichever filter the invisible cursor had stopped on. The pills now wear the app's own `CardFocusRing` (3 dp accent, painted over the pill so no layout moves when the ring arrives), and selection became the accent tint the tokens already define for a selected chip, behind an accent hairline: an accent ring around an accent pill is invisible, which is exactly what the user is left looking at after applying a filter, because focus stays on the pill that was applied. The selected pill's blurred accent shadow went with it — a zero-offset glow bled past the pill's own edge and read as a second edge, and on the last pill of the row it bled into the display's final pixels.
- The pill row keeps its margins at both ends. The row's 16 dp side padding sat *inside* the scroll view, which puts the scroll view's edges on the display's edges, 0 and 960; since focus reveals a pill by railing it against the viewport's trailing edge, the last pill was drawn with its fill on the display's last pixel and the scroll that got it there pushed the first pill out past x=0. The margins are the row's now — the viewport runs from 16 to 944 dp — so no pill can be painted in either gutter and the last one is revealed 16 dp short of the screen edge. The catalog's multi-filter row had the same padding in the same place and gets the same fix.
- Browse's poster grid spreads its columns across the canvas. It counted columns of the nominal 176 dp card while the two-row height budget actually drew a 112.8 dp one, so every card sat alone in a 220 dp cell: about 120 dp of empty canvas between neighbours, a 120 dp dead band at the right edge against the grid's own 16 dp left padding, and four sparse columns using barely half the canvas. The columns are counted from the card that is drawn now — seven of them on a 960x540 dp canvas, evenly spaced with even 16 dp margins — and the card itself is unchanged at the size it is documented at.
- The Watch Sources list is reachable from a couch. Its rows were a `MouseRegion` around an `InkWell`: an `InkWell` does install a focus node, but the row drew nothing when focus arrived, and nothing handed focus to the page at all — a pushed route opens with its own `FocusScope` holding focus, and a directional search from a node whose rect is the whole screen looks for a neighbour *outside* that rect, so three presses of Down left the screen pixel-identical and the centre button started nothing, which made the player unreachable without a pointer. The screen now owns the first row's node, requests it the moment a row exists and scrolls it into view, and every row is the app's own `FocusableCard` wearing `CardFocusRing` — so the D-pad has somewhere to start, somewhere visible to be, and a centre button that opens the source the ring is on.
- A dead stream can be left and replaced by remote. The "stream is not responding" overlay's two actions were Material buttons: focusable, but nothing ever moved focus onto them, and the player's own shortcuts answered every arrow and the centre button before the focus system saw them, because the gate that stands those shortcuts down knew only about the transport bar. The overlay takes focus as it appears, both actions are `FocusableCard`s wearing the 3 dp ring (Material's own treatment is a 12% tint, and nothing at all on the filled variant), the gate now asks about the overlay as well as the bar, and focus is handed back to the player's page node when the overlay goes away — left to fall to the route's scope, every arrow there was dead.
- The player names the stream it is playing instead of its scraped group tag. The badge beside the title was fed the source's raw `name`, which for a built-in ZPlayHTTP source is the group tag the site returned: `111477` over the video while the row that had been picked said `ZPlayHTTP · A111477`. Both surfaces now read one rule, `StreamSource.providerLabel`, so a chip over the video and the row it came from cannot name the same stream differently.

## [1.5.5] - 2026-10-11

- The music close actually stops the music. The bar's stop reached the controller's `clearQueue`, which empties the playlist and leaves the loaded track set, and the now-playing bridge publishes from that track on every controller notification — so the strip would have been published straight back on the next tick, with the audio still audible underneath it, and a play press afterwards would have resumed a file with nothing on screen to explain it. The controller owns a real `stop()` now: it clears the track, pauses and notifies, which is what publishes the empty frame the shell removes the bar for, and `play()` refuses to resume when nothing is loaded.

## [1.5.4] - 2026-10-11

- A television's own remote reaches the player again. The remote contract stood its shortcuts down whenever the player's page node did not hold focus, which on a real television is always: the pushed route takes focus, and the player's node sits inside it, so a key is delivered to the route and the player never hears it. Every arrow was then ignored while nothing in the transport was focused either, and the focus system was handed a direction it could not place — the reported player whose HUD is on screen and answers nothing, with only the platform's own media keys still working. The gate now asks the question the shortcuts actually care about, whether one of the transport's controls holds focus, and the player takes focus itself once it is on screen instead of relying on `autofocus` to win against a route's scope. Verified on a television emulator: one arrow press puts the ring on the pause button, and the row walks from there.
- The now-playing bar can be closed. It had no control that removed it — the transport only moved through a queue that stays non-empty while a track is loaded — so once anything was playing, the strip sat at the bottom of the shell on every screen with no way to dismiss it. The bar now carries a Close button, and a new `stop` command on the owner interface: the music bridge pauses and publishes the empty frame, and the audiobook player saves its place and leaves the screen it owns.

## [1.5.3] - 2026-10-11

- The player answers the remote and the finger again, on both form factors. The engine that shipped as the default, Media3, renders into a native `SurfaceView`: its own compositor layer sits above the window Flutter paints into, and a view that accepts focus takes the keys while one that accepts clicks takes the taps, before Flutter's tree ever sees them. That is the state both reports describe from opposite ends — a television where the only things that still worked were the platform's own media keys (play/pause, rewind, fast-forward, the volume rocker, none of which go through the focus system), and a phone where no tap did anything anywhere in the player, neither on the video nor on the transport's own buttons, while taps worked on every other screen in the app. The surface now declines focus and clicks, and the default engine goes back to mpv, whose frames arrive as a Flutter texture with no view of its own and so no way to stand between the viewer and the HUD. Media3 stays one tap away under Settings, Video, Playback Engine.
- A television no longer draws the phone's lock button. That lock is a tap target whose unlock is also a tap, so on a television it was a black screen with no way back: the only input there is a remote, which can press the lock but cannot tap the unlock.

## [1.5.2] - 2026-10-11

- The remote walks the player again. The HUD opens with the controls up, but nothing had handed them focus: on a television the player only ever moved focus into the transport through a request made while the transport was still unbuilt, and the four-second hide timer then handed focus back to the page node, whose rect is the whole screen. From there every arrow was a dead end — the arrows are deliberately ignored on a television so that the focus system owns them — and a directional search from a full-screen node finds nothing, so the only keys left were the ones the platform answers by itself: play/pause, rewind/fast-forward and the volume rocker. That is exactly the set the report listed, and the buttons past them — aspect, speed, audio, subtitles, subtitle sync and fullscreen in the transport, plus the Sources, copy-link and download controls in the top bar — could not be reached with the remote at all. A television's arrows now step *into* the HUD the way the centre button already did, so one press brings the controls back under the ring, every control in the transport is one press away, and the top bar sits one press up from the row.
- A finger that rolls is a tap, not a swipe. On a phone the transport could not be brought up at all: the player hangs its tap and its volume and brightness swipes off one gesture detector, so a finger that moved a few pixels on its way down gave the gesture to the drag recognizer, which cancels the tap before it ever fires, and the drag then flashed the volume readout and moved the level by a fraction of a percent. Every touch therefore read as a volume gesture and the controls stayed hidden, which is the state the report describes as being trapped in the player. A gesture is now read by how far it has travelled: under 12 dp it is a tap and toggles the HUD exactly as a clean tap does, and only past that does it become an adjustment — so the readout no longer flashes for a touch that never meant to change anything.

## [1.5.1] - 2026-10-10

- The landing page and the brand mark catch up with the app's red. The site was built on Signal Teal — the preset that leads the list only so it keeps its stored users — while the app's default has been Ember Crimson since the palette work, and the README lockup, `mark.svg` and the three shields.io badges were teal as well. The stylesheet's two accent variables are renamed from `--teal`/`--teal-ink` to `--accent`/`--accent-ink` and now hold the app's own values: `#f04e3c`, and the app's dark ink, which is what it picks as the foreground on an accent this bright (5.4:1 — white would have been 3.6:1). `docs/icon.png`, `mark.svg` and `lockup.svg` are re-tinted from the same pair, so the favicon, the repo header lockup and the app icon are one mark again rather than three shades of the same shape. Signal Teal itself is untouched and still selectable in Settings.

- The landing page shows the app instead of describing it. The old page was type on a dark canvas with no product image anywhere, which is what the site audit called out: nothing on it looked like ZPlay. It is built around the real screenshots now — the home screen bleeds across the top of the hero under a mask fade, then Watch, Read, Listen and Tune in as an unequal bento (no live-TV shot exists, so that cell is text), the accent picker with all eleven presets named and swatched, a quiet principles band, and the download grid that keeps its platform detection and its `Your device` chip. The type is Poppins, the app's own face, subset to the three weights the page actually loads and served from `docs/fonts` under the SIL Open Font License rather than from a font CDN, and the page ships `docs/og.png` (1200x630) with `og:image` and `twitter:card` tags so a link to the repo previews the product rather than the icon. Nothing personal is on it: the Continue Watching row was cropped out of the home shot before it was ever captured, and the footer credits the third-party artwork the screenshots show. The fourteen download URLs, the GPL fork statement and the platform-detection script are byte-for-byte what they were.

- The details card that grows under a focused title stays on screen. On the television the popped card's extras grew downward from the card's centre and nothing compared where they landed: the surface is the card's box plus the details panel, scaled 1.15 about the card's own centre, so a card in a low rail painted its synopsis and facts past the bottom of the window, and the only way to see them was to scroll the page under them - which, on a remote, reads as the card and the page fighting each other. The popped surface is now clamped inside the window it is drawn in, inset by 12 dp: the bottom overflow first, shifting up only as far as the bottom edge asks, then the top, where a surface taller than the usable window pins its top and keeps the overflow rather than jumping to the other edge, and the same rule on the horizontal axis so the card flush against the right edge of a rail no longer paints 13 dp past it. The displacement rides the pop's own progress, so at rest the copy still lands pixel-on-top of the card's slot with no jump when the remote arrives and it grows to its full value as the panel opens; it is applied through the animation rebuild that already runs every frame for the zoom, so keeping it live schedules no frame of its own. The extra's height is read from its own render box, which `SizeTransition` holds at full size on every frame because it reveals by clipping rather than by laying out smaller - so the clamp is computed against the fully-open surface from the first frame, not one animation late. The trade is deliberate and visible: on a low rail the focused card now lifts, because its details have to clear the bottom edge, and the alternative - pointing them off-screen - is what was reported. It is paint-only, in the root Overlay behind the pinned layout slot, so nothing in the page re-flows and the scroll extent is unchanged, which the new tests pin rather than assume: on the 960x540 canvas the same four D-pad presses from the same card produce identical scroll offsets and an identical `maxScrollExtent` with the panel and with the panel slot null, the low rail's surface measures 528 where it would otherwise paint to 624, and the right-most card's 973 becomes 948.

- The details card is twice the card it belongs to, and it stands aside when the page moves. The pop was a 1.15x paint scale of the card with the panel under it inside that same scaled surface, which had two visible consequences on a television: 1.15 stopped reading as the selected card, and the panel was only ever as wide as the card, so a synopsis wrapped into a column of short lines and grew downward off the bottom of the screen. The copy is now laid out at twice the card's own box on both axes, and the details panel under it gets that doubled width, so the facts and the synopsis run in long lines inside one large card rather than under a small picture. The card keeps its own shape and the artwork is decoded for the size it is painted at rather than upscaled from a smaller one, which is what the decode hint the copy hands its subtree is for; the growth is capped by what the window can hold together with the panel, whose height is measured rather than guessed, so a rail card spends the whole 2x while a tall poster spends what it can without pushing its own details off the screen - and the clamp from the previous change still keeps whatever grew inside the window. A card that is popped while the user scrolls the page also comes down at once rather than shrinking out over the row scrolling into view: the page announces its own key-driven scroll and every panel that is open at that moment is removed without the farewell animation, staying down until the focus leaves and returns. Only an *open* panel is taken down, so a press that both moves the focus and scrolls the page leaves the pop on the card the user just arrived at. The focus-reveal scroll is deliberately not announced, because that scroll exists to show the card that just took focus.

## [1.5.0] - 2026-10-09

- The rest of the app speaks Home's language. Outside Home every module had built its own chrome, its own buttons and its own cards, which is why the app read as several different ones: 32 pages drew a Material `AppBar`, and the shared rail and card widgets were used by three files each. Two structural changes carry most of it. The top bar now blends into whatever page is on screen rather than only over Home's hero: the shell measures the visible slot's own scroll (the outermost vertical scrollable, so a rail or a horizontal list never drives it) and paints the bar transparent at the top of the page, opaque by 32 dp — the same threshold Home's own row uses, so the two settle together — with Home's bespoke progress channel deleted rather than left as a second way to ask the same question. And every page now keeps the strip above its content transparent, spending `MediaQuery.paddingOf(context).top` itself, so nothing re-creates the opaque band with a hairline that the blend exists to remove. On top of that: Details runs the shared pills and section headers and drops 267 lines of bespoke button, header, card and edge-fade code; Browse's switcher sits on the canvas instead of an opaque band, and Library's band is gone too — which also fixed My List and Downloads each paying the shell inset a second time; Search's header tints only once results scroll under it; Discover, Calendar, Downloads and Collections lost their app bars, glows and drop shadows; all twenty Settings pages got the dark canvas and a transparent hairline-free band from one shared widget; and the IPTV, Anime, adult, multi-source and quiz surfaces were converted the same way, keeping only the containers whose fill is genuinely their content (a credential field, a colour swatch, a code box) and replacing every bare `InkWell` a remote could reach with the one focus primitive.
- The card that grows on focus is one card again on a television. Focusing a rail card popped the artwork to 1.15 and then hung a *separate* panel under it, 25% wider than the card on each side with its own fill, its own edge and its own gap — so from across the room it read as another row appearing above or below rather than the selected card transforming, which is what it looked like on the TV. The popped state is now a single surface: one fill, one radius, one clip, the artwork at the top and the facts, genres and synopsis directly beneath it at the card's own width, growing from the card's own box. The layout slot is still pinned to the card's resting size so neighbours never re-flow and the D-pad geometry never moves, the copy still paints in the overlay above its neighbours and still reads its position from the render box every frame (never a cached layer transform), and it is now passed to the animation as a stable child so a frame of the pop rebuilds only the transform. The extra info also stops printing the title a second time when the card already draws its own title block.

- Trailers play inside the app. Every trailer control — the hero's pill and a `Trailer` link on the title screen — handed a `youtube.com/watch` URL to the browser, because TMDb resolves a trailer to a YouTube *key* and nothing here can play one: Media3 and mpv have no extractor, and the only code that talks to InnerTube is the music extractor's. The key now goes into a medium-sized modal, ~78% of the window wide with a 16:9 stage, one `ZplayRadius.lg` surface, no border and no shadow, dismissed by the barrier, by `Escape`, by Back and by one 40 dp close control that also takes the focus ring, so a remote can reach everything in it and cannot leave it. The video is the YouTube embed inside a tiny local wrapper document loaded onto a real https origin, because the embed refuses to play a request that arrives with no referrer at all — the origin is what `loadHtmlString`'s `baseUrl` supplies on Android and what a virtual host mapping onto the wrapper's folder supplies on Windows, where WebView2 has no base URL for a string document. Android is also told the page may autoplay without a touch, which a remote is not, and on Windows the WebView2 environment is given Chromium's `--autoplay-policy=no-user-gesture-required`, because without it the embed opens on YouTube's own play button. Where none of it can work the trailer still opens: a machine with no WebView2 runtime goes straight to the browser as before, and an embed that fails after the modal is up says so and offers `Watch on YouTube` as a focused control rather than sitting on a spinner. Adds `webview_flutter`, `webview_flutter_android` and `webview_flutter_windows`; the last is a maintained Dart-3 fork of `webview_windows`, whose own SDK constraint no longer resolves, and it is not part of the federated family, so the Windows branch drives its controller directly. Requires the WebView2 runtime, which ships with Windows 11 and current Windows 10.

- Home is a landing page built around a title's artwork now, not a shelf of posters under an opaque bar. The featured title is a full-bleed canvas: the backdrop runs the full width of the window and up under the chrome, and three gradients — one for the bar, one for the text, one dissolving the band's bottom into the page — keep it readable over any still. The name arrives as its own clearlogo whenever one decodes and as plain type the rest of the time, never both. The actions under it are two quiet pills, a solid `Play` and a translucent `More Info`, with `Trailer` only where a trailer key exists, and a slow drift on the art replaces the 700 ms slide that read as movement rather than as a hero. The page keeps the ten-foot numbers it was measured against: the 236 dp band, the 92 dp of chrome above the content, and the carousel dots still on the first screen.
- The navigation bar blends into that artwork. The menus sat on their own opaque band above the page, so a full-bleed hero could not actually reach the top of the window; the bar is now painted over the page on tablet, desktop and television, and the pages are charged its height through `MediaQuery` instead of having the inset removed, which is what keeps every screen's content exactly where it was. On Home at the top of the page the bar draws no fill, no hairline and no separator — just a soft scrim so the labels stay legible over the frame, and the active destination marked by weight and the accent rather than by a filled pill. It turns opaque by 32 dp of scroll. Every other screen, and the phone's bottom bar, build exactly what they built before.
- Every control in the player answers a remote now, and the ring that says where you are is thick enough to find from a couch. The source list, the subtitle and audio pickers, the aspect and speed menus, the subtitle style sheet, the sync bar, the skip button and the label buttons were all still bare `InkWell`s: a D-pad could land on them and nothing drew, which is what "the highlight gets lost, focus is erratic" looked like on the television. They are `FocusableInkWell` now — the same focus node and the same ring the rest of the app already used — and the ring is a 3 dp accent line rather than 2, because at ten feet the 2 dp one was too thin to notice. Two sites that carried a tint on a `Material` kept it on a `Container`, so nothing lost its fill in the move.
- Windows updates install from inside the app. The updater downloaded the setup and then told you to close ZPlay and run it yourself; it now launches the installer detached, waits two seconds and exits, so the wizard picks up where the app left off. Android still installs in place, and Linux still opens the folder — which is what that platform's packaging actually allows.
- The Windows and macOS icons catch up with the rebrand. The mark went red in October and the Android launcher was regenerated with it, but `app_icon.ico` and the macOS icon set were still the teal one from September — so the window, the taskbar and the installer showed a logo the app had stopped using. Both are stamped from `assets/icon.png` at the sizes each platform asks for, and the executable's own icon resource is the new one; a taskbar button from an already-running copy can hold the old image until Windows rebuilds its icon cache.
- The four library modules finish the sweep, and each had the same two problems: chrome of its own, and content widgets copied instead of shared. Music was the worst of it — a 5,376-line page carrying three near-identical card implementations (track, album, playlist) and its own header, view band, rails and chips. It is one `_MusicCoverCard`, one `SectionHeader` per shelf, the shared `TabStrip` for filters, the shared `PillButton` for every primary action, and one 16 dp gutter where headings, rails and grids had each drifted to their own; the genre and radio tiles lost their index-cycled accent gradients and glass, and every panel lost its outline. Manga's shelf and details page lost their bordered, blurred boxes: chapter rows are ring-only rows whose state is a fill rather than a border, the CTA is a pill, and the details tags became one muted metadata line. Books lost its boxed title chip and control banner (Browse's own switcher already names the vertical), moved its font and format filters to the shared `TabStrip`, and replaced four filled colour badges with one metadata line; its reader's top and bottom chrome bars are now transparent over the page, which the existing gradient scrim already made legible. Audiobooks collapsed two gradients, four backdrop-blurred pills and a self-painted accent border into one accent glyph, the shared `TabStrip` and the shared arrows, and its chapter rows dropped both their border and their glow. Every one of them converted its bare `InkWell`s, `ElevatedButton`s and `OutlinedButton`s, and every interactive thing on them now carries the app's single 3 dp focus ring. What stayed bespoke is what a shared widget genuinely cannot express — the immersive reader and player bodies, the manga and book chapter tiles, and the reader's own Light/Sepia pickers, which are not built from `ZplayTokens` at all. One finding left on the table rather than changed silently: the audiobook player is pushed as a non-opaque route, so the whole shell keeps building and painting underneath the full-screen player. Making it opaque is a real saving, but it is a visible change to how the push reads, so it is yours to call.

## [1.4.0] - 2026-10-08

- Home's hero buttons no longer draw overflow stripes on a phone. The three pills sat on a row that wants about 490 dp, so at 360 dp it overflowed by 80 and at 412 dp by 28 — and because an `IndexedStack` lays out every screen rather than only the one on show, the stripes appeared on Browse, Search, Library and Settings too, which reads as the whole app being broken rather than one row on Home. The row wraps instead, moving a pill to a second line where it cannot fit, and the carousel already reports the height its content actually took, so this costs the row below space only on the screens where the row genuinely would not fit. It is now swept at both widths so it cannot come back unnoticed.
- Back no longer drops you out of the app. On any screen other than Home it now returns you to Home, with that screen still where you left it, instead of leaving, and at Home it asks for a second press: `Press back again to exit` appears for two seconds, so a single stray press on the remote can no longer send you to the launcher. Nothing above the shell changes — a title page, a dialog and the player still close on the first press, and the player keeps its own lock and fullscreen behaviour.
- Source cards now show a bitrate, so two streams can be compared on more than a guess at the name. It resolves in three tiers: a rate written in the release name, the peak variant read off an HLS master manifest for direct streams, and an estimate from file size and runtime for torrents and Debrid, which state no rate at all. Only the first two are measurements and only they are drawn plainly — an estimate carries a leading `~` so it can never pass for a number that was read rather than inferred. The manifest is peeked at lazily, from the badges actually on screen, because one title fans out to hundreds of sources across the built-in scrapers and your addons and a blanket probe would put every one of them on the wire; a single request's answer is remembered per URL, misses included. The probe reads only the playlist and gives up if a response is not one, so a direct stream can never cause a whole multi-gigabyte file to be pulled in just to label it. Carried over from the project this is a fork of, which added it after we split, and adapted to our token layer and our source lists.
- The search bar can be typed into again. The shell marks each slot page's own focus node as untraversable, so a node covering the whole page cannot trap a remote, and it found that node by walking the focus tree with a "we are inside the page now" flag. That flag only works while the focus tree nests the way the widget tree does, and it does not: the shell's own `ExcludeFocus` sits between a page's contents and the page, so the flag was never raised and every control below was classified on its own. All of them were marked, and on Search that meant the field's own node was left unable to request focus — the bar rendered, accepted taps, and never took a cursor, which is why typing did nothing. A node is now marked only when it sits inside the page, is not itself inside another such node, and actually has focusable content hanging off it; a leaf control is left alone. The covering test is what makes this a page property rather than a control property, and in the Flutter this builds against `Scaffold` installs no focus node at all, so on most pages the only node inside the page is a leaf control.
- The source list inside the player now searches every addon you have installed, not only the one already playing. It was asking the targeted endpoint for the current source's provider, so a title whose source came from the built-in scrapers showed nothing but those scrapers and never contacted your other addons at all — the ones the details screen had already listed. The list is for finding something else to play, so it now fans out the same way the pre-play screen does, and the source you are watching stays in it. The panel says so now too: it was still headed `Provider: <the one you are playing>`, which named a single provider over a list that had become every one of them, and choosing another source used to restart the scrape and blank the list you were reading.
- Titles that arrive as `tv` no longer lose every addon in silence. The catalog and details layers say `tv` for episodic content while the Stremio route only knows `movie` and `series`, so the manifest check discarded each addon without a request and without a log line, and the ones that survived would have been asked for an endpoint that does not exist. The alias is now translated at the addon boundary, and only there: the built-in scrapers still receive `tv`, which is what they expect.
- The built-in HTTP scrapers no longer hand you a completely different show. KissKH scored an unmatched result as zero while treating anything above `-1` as a winner, so the first drama the search returned was accepted for any title — an unrelated Korean soap was the visible result. Three more of them, LookMovie, LMScript and XDownloader, fell back to the first search result the same way. A title that matches nothing now yields nothing, and the episode-number fallback on a drama that genuinely matched is unchanged.
- 4K stuttering on small Android TVs is diagnosed and fixed. On a 2 GB Chromecast with Google TV, ZPlay played 4K with 1,389-1,917 ms of decoder latency and about 1.5 dropped frames a second, while YouTube decoded the same device in 131-329 ms — so the device was never the limit, the playback engine was. The bundled libmpv only ships `mediacodec-copy` hardware decoding, so every 4K frame was copied out of the hardware decoder into system memory and then composited into a Flutter texture. Android's own ExoPlayer/Media3 has joined it behind one contract, rendering into a SurfaceView so frames reach the display without that copy: the same file comes up in **904 ms with zero dropped frames**, at a third of the CPU and about a third of the memory. You can pick between them under Settings, Video, Playback Engine — ExoPlayer is the default on a television and falls back to mpv anywhere it is not available, while torrents and live television always use mpv because Media3 cannot open them. Video is capped at 1080p on the ExoPlayer path, because a panel cannot show more and letting adaptive quality pick a 2160p rendition on 2 GB is the surest way back to the crash this replaces. mpv keeps the full subtitle styling and the upscaling presets, so the choice is yours. Both engines were then run on the television itself: the transport bar draws over the ExoPlayer surface and the remote drives it — centre key pauses, the seek bar and focus ring answer the D-pad exactly as they do on mpv.

## [1.3.1] - 2026-09-26

- Debrid failures are now understood instead of printed. A refused torrent used to reach you as the provider's own output, `Exception: Real-Debrid rejected magnet (451): { "error": "infringing_file" }`, and one refusal could end the whole chain. Every failure is now sorted into what it actually means, and the player acts on the sort. A source that was refused, or that is not ready yet, moves on to the next ranked one immediately instead of waiting out the watchdog, so a dead entry no longer costs you nine seconds and the attempt behind it. A problem with your Debrid account stops instead, because every source fails the same way and walking the chain would only hide the one thing you can fix.
- A source Debrid turned down keeps its place in the list with a quiet marker on it instead of disappearing, and the automatic search stops spending attempts on it. A permanent refusal is remembered for good and a softer one for a fortnight, so the same dead link is not put back in front of you the next night.
- Sources you choose by hand now get the same handling as the ones the app picks. They are replaced by a ranked alternative when they fail, and the source search screen still appears only after the app has actually taken over a choice you made, never during the first attempt.
- Your Debrid key can now reach your Stremio addons. An addon URL may carry `{realdebrid}`, `{torbox}`, `{alldebrid}`, `{premiumize}`, `{debridlink}` or `{debrid}`, and the key you saved is substituted when the request is built, for the manifest, the catalog, the metadata, the streams and the subtitles alike. A placeholder naming a service you have not set up is left standing, so a misconfigured addon fails visibly instead of quietly asking the wrong service, and your key is never written into the saved addon, so rotating it keeps working without editing anything by hand.
- Addons gained a Debrid section with Connect and Disconnect, and a catalogue of Debrid addons to start from. Torrentio ships with it, one entry per service, each naming itself after the service you are connecting.
- Torrent sources now reach Debrid while the local P2P engine is switched off. Turning Debrid on used to switch the local engine's indexers off with it, so the magnets Debrid resolves in the cloud were discarded before anything asked for them, and the Debrid marker matched nothing on the built-in entries. A working Debrid service now brings its magnets with it whatever the local engine is set to. They are counted and marked as Debrid playable, and they stay listed when the local engine's own streams are off, so a verified account actually shows Debrid sources.
- The keys inherited from PlayTorrio are gone. They were never ZPlay's credentials to ship, so all six now ship empty, and the fallback that quietly borrowed the inherited TMDb key is gone with them. If you were relying on them, you will notice. Wyzie subtitles, both Audionest services, Paper2Audio, the Films365 downloader and the VidGod cache are each off until a key of your own is supplied, in Settings under Service API Keys, or injected at build time. Nothing is left half working, and the one place a key is not needed is unchanged: the six 1990s rails still show their built-in picks with no TMDb key at all, exactly as before.
- Search now says so when its sources fail. If nothing it asked came back, it reports `Search could not reach its sources`, tells you how many of how many sources did not answer, and offers a retry, instead of telling you the title does not exist. When only some sources answer, the results that did arrive are shown with a quiet count of what is missing, because a partly empty list is not the same thing as an empty one.
- A movie with no playable source no longer sends you back to episodes. A film has no episodes behind it, so the empty state now names only the exits that are actually on screen.
- The play button on Continue Watching is visible on touch devices without waiting for a hover that never comes. It was revealed on hover alone, which a touchscreen and a D-pad cannot do, so on those devices the tile showed no way to start the film.

### Windows: one-time profile migration

- The rebrand moved the folder your profile lives in, and it moved silently. Windows takes that path from the app's own name, so every install up to and including the rebrand wrote to `%APPDATA%\com.example\playtorrio` and every install after it writes to `%APPDATA%\tzero86\zplay`. A first launch after the rebrand therefore opened an empty app: no settings, no watchlist, no addons, no downloaded media index, no TorrServer database.
- 1.3.1 copies the old profile into the new location on first launch, before anything reads it, so an existing install comes up exactly as you left it.
- The old folder is left where it was. Nothing is moved and nothing is deleted, so the original is still there if anything about the new profile disappoints you.
- A destination that already exists is never overwritten, and a half-finished copy is never moved into place. If you have already run a build from after the rebrand and reconfigured it, that profile is yours, and a stale copy from the previous install will not be laid over it.
- A fresh install has no old profile to find and simply starts clean, and so does every platform other than Windows.
