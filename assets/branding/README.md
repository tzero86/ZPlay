# ZPlay brand

The mark: a solid squircle with the letter cut out of it. The Z reads as a hole
rather than as ink drawn on top, so the identity carries its own figure/ground
trick instead of a glyph sitting inside a container.

```
assets/branding/zplay/
├── mark.svg        square mark, colour      (1:1, the icon)
├── mono-mark.svg   square mark, single ink  (1:1)
├── lockup.svg      mark + "ZPlay"           (horizontal)
└── mono.svg        mark + "ZPlay", one ink  (horizontal)
```

## Why this mark

**No play triangle.** Upstream's placeholder was a play glyph in a rounded
square — the most generic mark in streaming. Earlier directions explored a play
core inside an orbit ring; dropping the glyph entirely was the point.

**Squircle, not a square.** It reads as an app icon rather than a swatch, and it
survives being placed inside a launcher's own mask.

**Heavy letter, tight margins.** A thinner cut was tested and only just survived
16px — its counters came out around 1.5px. The shipped weight puts more ink in
the letter and less in the dead tile, which is what holds up at favicon size.

**The Z is opaque near-black, not a real transparent hole.** A transparent
counter would show through as white-on-red at about 3.6:1 on a light taskbar,
still short of the 4.5:1 a small counter needs. Opaque ink means the icon is self-contained and legible on
any surface. `mono-mark.svg` is the exception and keeps a genuine transparent
counter, because a single-ink mark is placed on a background you control.

## Colour

One accent: Ember Crimson, the app's default preset.

| Role | Hex |
|:--|:--|
| Accent / tile | `#F04E3C` |
| Letter ink | `#0A0D12` (the app's dark base) |
| Wordmark | `currentColor` |

Every file except `mark.svg`'s two fills is `currentColor`, so the same artwork
works on the dark base (`#0A0D12`) and on a light surface without a second copy.

## Re-tinting

- **Colour mark / lockup**: change the single `#F04E3C` fill.
- **Monochrome mark / lockup**: nothing to change — it inherits.

## Sizes

| Use | Source | Notes |
|:--|:--|:--|
| App icon, all platforms | `assets/icon.png` (1024) | Regenerated by `flutter_launcher_icons` from `assets/icon.png` |
| In-app small art | `assets/icon_small.png` (256) | The only variant bundled into the app |
| Windows `.ico` | `assets/icon.png` | 16/24/32/48/64/128/256. **`flutter_launcher_icons` writes a 48px-only ICO** — regenerate the multi-size file by hand after running it |
| Web / README | `mark.svg` | Vector, scales anywhere |

The app-icon raster is deliberately **tighter than the in-app mark**: the mark
sits inset at 72% of its 128 box so it balances against the wordmark, but an icon
inset that far renders small once iOS or Android applies its own mask. The
rasteriser therefore draws the tile at 92% of the canvas.

## Not done yet

- **Android adaptive icons.** `flutter_launcher_icons` is configured without
  `adaptive_icon_background` / `adaptive_icon_foreground`, so Android gets legacy
  icons. A proper adaptive set wants the letter alone as the foreground on a flat
  accent background, so the launcher's mask does the shaping — otherwise the
  squircle gets masked inside a masked tile.
- **Linux.** The config lists `linux: generate: true` but `flutter_launcher_icons`
  has no Linux target, so nothing is emitted; the AppImage icon comes from CI.
- **iOS alpha.** `remove_alpha_ios: true` flattens the transparent corners. Kept
  as-is because the iOS build here is an unsigned sideload; the App Store would
  reject alpha anyway, but the corners need checking if that ever changes.
